# 部署与配置

## 本机地图配置

frontend/.env.local（可从.env.example复制，API_PROXY_TARGET默认指向本机8000）：

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
VITE_AMAP_JS_KEY=填写自己申请的Web端JSAPI_Key
VITE_AMAP_SERVICE_HOST=/_AMapService
```

frontend/.env.amap-server.local（从.env.amap-server.example复制）：

```dotenv
AMAP_SECURITY_JSCODE=填写与该JS_Key配套的安全密钥
```

jscode只由Node开发服务器读取，不使用VITE_前缀。配置后完全重启npm run dev。当前前端Vite配置使用Node的loadEnvFile，因此沿用已验证的Node24环境。

底图配置成功后，/api/v1/map/demo提供武汉模拟点位与示意连线；不需要后端Web服务Key。它们不对应真实配送地址、道路或GPS，不用虚线距离计算ETA。候选图仅为预览，全部必要人工确认后才生效。

## 真实AI和道路

根目录私有.env按需填写：

```dotenv
AGENT_MODE=deepseek
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=填写账号实际开通的模型名
DEEPSEEK_API_KEY=填写自己的模型Key
AMAP_WEB_SERVICE_KEY=填写自己的高德Web服务Key
```

只启用需要的能力：未配置模型Key时保持AGENT_MODE=local。地图JS Key/jscode与地图Web服务Key不互换。

修改根目录.env后重新创建后端服务使环境变量生效。通过/map/geocode取得候选、人工确认后PUT /map/nodes/{node_id}维护真实GCJ02点位，再使用/map/route查询实际道路。显式/map/routing/refresh成功后计算才使用新真实矩阵；最多21点、总预算60秒、完整发布，失败不发布半张图。

## 已有环境与数据

升级前备份并停止旧API、worker、维护器，再docker compose --env-file .env up -d --build --wait，迁移容器自动增量升级至0004。不要删除数据卷或重新seed以代替升级。

普通停止docker compose --env-file .env down，保留卷。恢复时沿用相同.env与Compose项目名。固定基准验证脚本backend/scripts/demo.py会修改业务数据，仅在全新隔离演示库运行一次。

## 生产部署

后端支持外部PostgreSQL/Redis，华为云RDS/DCS连接模板见deploy/huaweicloud。模板不代表已开通云资源。

前端npm run build生成dist。生产静态站点需反向代理/api到后端，并实现同源/_AMapService及/_AMapService/_status，安全密钥由服务端注入。当前仓库的server/amapProxy.ts是Vite开发中间件，vite preview和纯静态托管不会运行它。不要把AMAP_PROXY_TARGET指向尚未实现此代理的业务API。

仅在配置和上游已核验后才应由生产代理返回configured:true。正式环境需要固定允许上游、请求路径和方法限制、超时、体积上限、限流、错误脱敏、不转发业务JWT/Cookie及禁止在日志记录jscode。HTTPS证书、域名、备份与资源权限按实际环境配置。

本仓库提供可复现的本机演示与后端云连接模板；未承诺未经验证的生产代理、真实模型效果、道路货车限制或比赛合规结果。
