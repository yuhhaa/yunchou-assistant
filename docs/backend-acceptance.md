# 运筹助手后端验收范围

依据 2026-10-26 两份项目文档，契约版本 1.0。此文件记录实现需要通过的检查，不代表尚未执行的检查已通过。

## 核心业务基准

模拟时间 10:00，V01 在仓库 W；O001/A、O002/B、O003/C 都已装车，每站服务 5 分钟，软窗口最晚时间分别为 10:50、10:35、11:15。原路线 ABC，原路线版本 1。W-A/W-B/W-C/A-B/A-C/B-C 的分钟数为 15/10/25/10/20/15，米数为 8000/5000/12000/5000/10000/7000。该固定样例方向对称；计算模块不应假定其他输入也对称。

1. 延误 20 分钟时，ABC 的 O002 预计 10:50 到达，迟到 15 分钟。
2. BAC 到达 B/A/C 分别为 10:30/10:45/11:10，累计迟到 0 分钟。
3. ABC 与 BAC 均为 20000 米；变动订单 2、换车 0、相对顺序反转 1。
4. 批准 BAC 只进入 APPROVED_PENDING_ACK；司机接受且再次核验后才 ACTIVE。
5. 在批准前将延误改成 40 分钟并增加事件版本，旧候选被 409 拒绝，路线不变。

## 额外工程检查

- PostgreSQL 真实事务下并发批准同一车辆只有一个有效预留；同键并发请求只产生一个操作。
- Worker 重复投递、数据库提交后消息投递失败、运行租约过期恢复均不得重复发布结果。
- 快照持久化完整输入，候选持久化完整目标路线；变化摘要不能替代业务事实。
- JOB 查询成功与业务成功区分；无解、后台失败、过期分析分别表达。
- T05 不允许读取 CHAT 作业；前端 JOB 查询可读取本人 CHAT 作业。
- 相同会话只运行一轮对话，刷新后可通过 job_id 恢复。
- 工具入口与业务入口复用权限、版本和事务逻辑；激活不能由模型调用。
- 司机生成候选后，调度端能通过授权事件视图发现影响分析与候选，不依赖复制隐藏 ID 或重新计算；不得借此读取他人聊天。
- 真实 AgentArts 网络、动态签名凭据注入与原生字段映射需实际环境验证；本地模拟不算平台验收。
- OpenAPI 的五个 operationId 与文档一致；错误与成功使用统一外层。
- Compose 启动健康检查、迁移和显式数据初始化；普通启动不得覆盖现有业务数据。
- 数据库与 Redis 不向外网发布；示例密钥不作为生产默认值；日志不记录密钥和完整隐私输入。

## 测试与联调的分工

- `backend/tests/test_solver.py` 验证固定路线基准、指标口径、装载与路线硬约束。
- `test_contract.py`、`test_permissions.py`、`test_idempotency.py`、`test_lifecycle.py` 验证 HTTP 契约、权限、幂等和审批执行；其中 PostgreSQL 专用用例验证真实并发写入与竞争批准。
- `test_jobs.py`、`test_chat.py`、`test_platform.py` 验证任务恢复、通知去重、会话隔离和平台适配边界。注入过期运行状态的恢复测试，与真实 Redis/Celery 启停联调分别记录。
- OpenAPI 导出、数据库迁移和 Docker 启动需要单独验证；单元测试通过不能代替这些检查。
- AgentArts 账号内的网络可达性、动态凭据映射和实际返回解析仍需真实环境验收；本地业务闭环不能替代这部分结果。
