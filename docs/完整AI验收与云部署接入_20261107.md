## 本机重复执行

在安装后端依赖的Python 3.12环境中，cd backend：

```powershell
python scripts/validate_ai_tools.py --live --full --env-file .env.ai.local --report ../ai-full-live-report.json
python scripts/validate_ai_tools.py --live --full --delay 15 --env-file .env.ai.local --report ../ai-full-live-report-delay15.json
python -m pytest tests/test_ai_continuation_context.py tests/test_deepseek.py tests/test_chat.py tests/test_lifecycle.py -q
```

--live明确调用真实收费API；--mock仅覆盖两轮协议，不支持--full。--full的人工步骤由验收脚本按角色模拟，生产仍须用户主动批准/接受；不能把脚本的自动批准代码接到模型业务逻辑。

## 前端怎么使用

当前后端仓库已包含frontend源码，所以本次能定位入口；并未读取独立私有前端仓库的最新版本。

1. 后端实际运行配置使用AGENT_MODE=deepseek、有效DEEPSEEK_BASE_URL/MODEL/API_KEY，更新API及worker-chat配置；Key只留后端。
2. frontend/.env.local设API_PROXY_TARGET=http://127.0.0.1:8000（或当前可达后端根地址，不能重复加/api/v1）。使用Vite代理完整保留/api/v1。地图独立配置，不影响业务聊天API。
3. frontend目录执行npm ci、npm run dev -- --port 5175。浏览器打开本机5175并用真实测试账号“登录工作空间”。不要点“体验独立演示空间”或“武汉联调本地样例”，这两者走前端Mock，不会请求DeepSeek。
4. 电脑端顶部点“事件协同”（aria-label为“打开智能助手”）；司机端底部“智能协作”也会打开同一助手。异常上报弹窗内有“改用自然语言与助手沟通”。
5. 选择授权订单O001，发送“堵车了”，补充“预计晚20分钟”；保留同一个conversation_id。等待计算任务完成后手动“继续/生成恢复方案”。调度在事件工作台比较并批准，司机在原接收入口接受。
6. F12 Network应看到POST /api/v1/chat返回202及GET /api/v1/jobs/{id}轮询。readiness应报告deepseek，但真实成功还要看CHAT结果、业务事件和计算引用。模型请求发生在服务器，不应在浏览器看到DeepSeek Key或直连模型请求。

## 云端复用与验收门槛

运行时本就从环境配置读取模型，不需要为上云重新搭Agent。合入本次修复并推送仓库后，在deploy/huaweicloud原配置中接入实际RDS PostgreSQL、DCS Redis和计算主机；先备份旧库、增量迁移到0004，不重seed既有库。新建测试环境另seed一次。

前端构建产物放HTTPS静态站点；反向代理/api/v1到业务API。Vite API_PROXY_TARGET只在开发生效，不能以为设置它就配置了生产反代。地图/_AMapService单独部署，其Key与业务JWT、DeepSeek Key分别管理。

云端验收使用独立测试账号/演示数据，通过浏览器真实HTTPS请求及Celery排队执行同一完整顺序，不用本脚本的同步函数执行冒充队列通过。记录版本、区域、资源、模型、request_id、conversation_id、CHAT/分析/候选JOB、事件及最终状态。

部署前必须补齐：PostgreSQL并发/迁移、Redis和worker丢失恢复、跨租户/角色权限、写入重试幂等、候选300秒与批准预留60秒过期、模型故障/限流和预算、真实地图（若展示）、HTTPS/CORS/前端构建与页面验证。保留旧模型调用失败后的业务回执恢复机制。

共享演示环境会真实写数据，测试前由团队指定独立租户/数据库，不将多个验收人同时操作的旧库当成干净基准。

## 仍然存在的限制
